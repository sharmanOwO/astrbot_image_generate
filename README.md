# image2.5 生图插件（image_generate）

AstrBot 生图插件。支持聊天模型调用 `generate_image` Tool 进行文字生图，调用 `edit_image` Tool 进行图生图，也可以通过 `/文生图`、`/图生图` 命令手动触发。


## 安装与快速开始

此仓库同步自 2026-10-27 的运行服务器源码，插件版本保持 `1.3.1`。

1. 在 AstrBot 插件管理中通过仓库地址安装：`https://github.com/sharmanOwO/astrbot_image_generate`。
2. 手动安装时，将仓库内容放入 `data/plugins/image_generate/`。在运行 AstrBot 的 Python 环境中安装 `requirements.txt` 中的依赖，再重载插件。
3. 在插件配置中填写自己的接口地址和 API Key，确认服务商支持所填写的模型。
4. 发送 `/文生图 一只坐在窗边的猫`；需要图生图时附图或引用图片后发送 `/图生图 改成水彩风格`。

仓库不包含服务器实际填写的配置、API Key、聊天记录或生成图片。这里的模型名称是插件使用的请求标识，不代表所有服务商都支持。

依赖安装命令中的 `python -m pip` 表示使用当前 Python 对应的包管理器；`-r requirements.txt` 表示按依赖文件安装。请先进入插件目录；此命令不升级 AstrBot、NapCat 或 QQ。

```bash
python -m pip install -r requirements.txt
```

## 配置

安装插件后，在 AstrBot WebUI 的插件配置中填写：

- `api_key`：中转站 API Key，不要包含 `Bearer` 前缀。
- `api_url`：生图接口地址，默认使用 `https://api.apiqik.com/v1/images/generations`。
- `edit_api_url`：图生图接口地址，默认使用 `https://api.apiqik.com/v1/images/edits`。
- `model`：文生图和图生图共用的模型名称，默认 `gpt-image-2-5-sunburst`，留空使用默认值。
- `request_timeout`：请求读取超时，默认 480 秒，范围 30～600 秒；连接超时为 30 秒。requests 的读取超时是等待数据的超时，不是整个请求的总时限。

模型由配置决定，每次生成 1 张图片。文字生图由聊天模型根据用户要求选择尺寸：方图 `1024x1024`、竖图 `1024x1536`、横图 `1536x1024`。未明确要求画幅时根据画面内容判断，无法判断或未传入尺寸时使用 `1024x1024`；不会额外向用户播报所选尺寸。

## 使用

请在 AstrBot 中启用本插件的 `generate_image` 和 `edit_image` 工具，并确保当前聊天模型支持 Tool Calling。

文字生图时直接提出要求，例如：

```text
请生成一张坐在窗边看雨的橘猫图片，水彩插画风格。
```

图生图时，在同一条消息中附带一张或多张图片，或者引用一条包含图片的消息，然后直接用自然语言提出修改要求。聊天模型会调用 `edit_image` Tool。

`edit_image` Tool 可以选择标准尺寸 `1024x1024`、`1024x1536`、`1536x1024`，也可以传入 `original` 依据第一张参考图计算输出尺寸；尺寸会经过下文的放大与 16 倍数矫正，并非保证原像素尺寸不变。插件会在每次请求中读取所有参考图片的宽高，并把这些原图尺寸加入本次可选尺寸集合；不会修改跨会话共享的全局集合。

## 手动指令

不需要聊天模型调用工具，命令后的尺寸选项必须是第一个独立词，与描述之间用空格隔开。

| 指令 | 别名 | 默认尺寸 |
| --- | --- | --- |
| `/文生图 <prompt>` | `/wst`、`/w` | 1024x1024 |
| `/图生图 <prompt>` | `/tst`、`/t`、旧指令 `/tushengtu` | 1024x1024 |

两种指令都支持以下尺寸选项：

| 选项（任选一种写法） | 尺寸 |
| --- | --- |
| `-s`、`方`、`方图`、`1024x1024` | 方图 1024x1024 |
| `-v`、`竖`、`竖图`、`1024x1536` | 竖图 1024x1536 |
| `-h`、`横`、`横图`、`1536x1024` | 横图 1536x1024 |

图生图额外支持 `-[i]`：按消息组件遍历顺序（遇到引用时先展开引用中的图片），使用第 i+1 张图片的尺寸。索引从 0 开始；`-[0]`、`-`、`-[]` 等价。索引只决定尺寸参考，不会删掉其他上传图片。索引越界或缺少描述时返回提示。

```text
/文生图 一只坐在窗边的猫
/w -v 雨夜中的街道
/wst 横图 山间湖泊
/图生图 将所有参考图融合成水彩画
/t -h 将人物放在同一场景
/tst -[1] 保留主体，改成油画风格
/t - 换成雪景
```

图生图会上传当前消息及引用消息中找到的全部图片，以多个 `image[]` 字段发送。支持 JPEG、PNG 和 WebP；单张最大 25 MB，全部合计最大 50 MB。

在 QQ/OneBot（AstrBot 的 `aiocqhttp` 适配器）上，手动图生图指令未找到任何附带或引用图片时，会自动下载**发送指令者的 QQ 头像**作为唯一参考图。例如 `/tst 改成水彩头像` 默认输出 1024x1024；`/tst - 改成水彩头像` 使用头像尺寸并经过下述尺寸矫正。`/图生图`、`/t`、`/tushengtu` 同样支持。头像不是被引用者或被 @ 用户的头像。

附带或引用图片优先；图片读取失败时会报错，不会偷偷换成头像。头像下载失败、格式无效或当前平台不支持获取头像时，会提示附带图片。只有头像时索引仅支持 0，`-[1]` 等会提示越界。聊天模型调用的 `edit_image` 工具仍要求消息中有参考图片。

引用尺寸会先经过现有矫正函数：面积不足 655980 时先按宽高同时翻倍放大，再把宽高分别调整到最接近的 16 倍数。例如 `1001x777` 调整为 `1008x784`。这里只矫正请求的输出尺寸，不修改上传图片。实际支持的尺寸仍由所配置接口及模型决定。

## 网络请求

插件直接发出的生图请求及结果图片下载使用 `requests`。文生图通过 `json=payload` 发送 JSON；图生图通过 `data=payload, files=files` 发送 multipart 文件表单，由 requests 自动生成 Content-Type 和 boundary。更换 HTTP 库不会改变接口要求的上传格式。

同步请求通过 `asyncio.to_thread()` 放到工作线程执行，避免阻塞 AstrBot 的事件循环。停用插件会取消后台协程，但已经在线程中执行的 requests 请求会继续到完成或超时，不会被强行中止；取消后不会再发送结果。参考图组件的读取仍交给 AstrBot 的 `convert_to_base64()`。


## 指令与 AI 工具的关系

工具调用是聊天模型决定调用插件函数；手动指令则直接进入插件。文生图指令解析参数后调用与工具相同的 `generate_image` 函数。图生图两种入口共用 `_start_edit_task`、`_edit_and_send` 和请求代码，但入口行为不同：指令默认方图，工具默认 `original`；只有手动图生图在缺少图片时会尝试发送者头像。

模型、API Key 和接口地址都从同一份插件配置读取。配置模板中的默认接口与 Python 代码中“配置项不存在时”的旧回退接口不一致；安装后请明确填写 `api_url` 和 `edit_api_url`，不要靠省略配置来选择服务商。本次同步保留服务器源码原有行为。

## 测试与排错

仓库附带 `tests/test_plugin.py`。先安装依赖，在仓库根目录执行下面命令：`-B` 避免写入字节码缓存；`-m unittest discover` 使用 Python 自带测试工具查找测试；`-s tests` 指定测试目录；`-v` 显示每项结果。测试使用模拟的 AstrBot 对象和本地 HTTP 服务，不调用付费生图接口，也不发送 QQ 消息。

```bash
python -B -m unittest discover -s tests -v
```

本次对导出源码实际运行了以上测试：共 15 项，12 项通过；3 项测试方法报告合计 11 处子测试或断言失败，当前报告均为头像相关的回复文案与旧测试预期不一致。例如源码回复“开始生成图片喵~”，旧测试要求包含“你的 QQ 头像”。本次保留运行服务器代码与附带测试原样，未为上传而修改功能，也不声称测试全部通过。

- 提示未填写 API Key：检查插件配置；不要把密钥粘贴到 Issue 或日志截图。
- 接口返回错误：核对服务商地址、模型权限、余额与尺寸支持情况。
- 图片已收到但发送报超时：可能是消息平台发送确认超时；生成成功与消息发送成功是两个阶段，应结合平台日志判断，避免反复生图造成重复扣费。

`.gitignore` 用于排除本地配置、私钥、Cookie、缓存和生成结果。它不会替已经上传的文件消除历史记录，因此每次提交前仍应检查差异。
